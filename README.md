# Код — изучение Python

Мобильное PWA-приложение с тремя уровнями Python (90 уроков), интерактивной практикой, тестами и сохранением прогресса на устройстве.

## Публикация на Vercel

1. Создайте GitHub-репозиторий и загрузите в него файлы проекта. Не добавляйте `.env`, ключи API или другие секреты.
2. Войдите в [Vercel](https://vercel.com), выберите **Add New → Project** и импортируйте GitHub-репозиторий.
3. Для проекта оставьте **Framework Preset: Other**, **Root Directory: `./`** и используйте настройки сборки из `vercel.json`. Команда сборки — `node prepare-vercel.js`, папка публикации — `.`; пакеты устанавливать не требуется.
4. Нажмите **Deploy**. Для следующих изменений достаточно отправлять новые коммиты в подключённую ветку GitHub.
5. В настройках проекта Vercel откройте **Settings → Domains**, добавьте свой домен и настройте DNS по подсказкам Vercel. Production-сборка автоматически подставит production-домен в canonical/OG/Twitter метаданные. Preview-деплои помечаются `noindex`.

После публикации проверьте сайт по HTTPS и установку на телефон через меню браузера («Добавить на главный экран» / «Установить приложение»). Для карточки предпросмотра ссылки замените `social-preview.png` на своё изображение 1200×630 px. Аналитика выключена по умолчанию; если подключаете Яндекс Метрику, задайте её ID в `config.js` и проверьте текст согласия/политику для своей аудитории.

## Регистрация и синхронизация через Supabase

1. Создайте проект в [Supabase](https://supabase.com) и дождитесь его готовности.
2. Откройте **SQL Editor**, выполните содержимое `supabase-schema.sql`. Таблица использует Row Level Security и разрешает чтение/изменение только строки с `user_id`, совпадающим с `auth.uid()`.
3. В **Authentication → Providers → Email** оставьте включённым подтверждение адреса. В настройках безопасности задайте минимальную длину пароля не менее 12 символов и оставьте включёнными ограничения частоты запросов. Перед публичным запуском подключите собственный SMTP-провайдер и подтвердите домен отправителя: тестовая почтовая доставка Supabase может быть ограничена.
4. В **Authentication → URL Configuration** задайте `Site URL` как production URL сайта и добавьте в список redirect URLs точный production URL и `http://localhost:3000/` для локальных проверок. Например, если сайт открыт по адресу `https://my-python-course.vercel.app`, добавьте именно `https://my-python-course.vercel.app/`. Preview URL используются только если вы явно добавили их в allowlist. Эти настройки разрешают Supabase перенаправлять пользователя на ваш сайт после нажатия ссылки подтверждения или сброса пароля; адреса, которых нет в списке, сервис отклонит.
5. В **Project Settings → API** скопируйте Project URL и публичный `anon`/publishable key в `config.js` в поля `supabaseUrl` и `supabaseAnonKey`. Это публичный клиентский ключ: защита данных обеспечивается RLS. **Никогда не вставляйте `service_role` или secret key в `config.js`, HTML, GitHub либо переменные браузера.** Закоммитьте `config.js` и отправьте изменение в GitHub, чтобы Vercel обновил сайт.
6. Проверьте регистрацию: создайте аккаунт, перейдите по ссылке подтверждения из письма, войдите и завершите урок. Затем войдите в тот же аккаунт на другом устройстве — прогресс и серия занятий загрузятся из облака. Сброс пароля также отправляется по почте.

Адреса, используемые на сайте, и прогресс аккаунта обрабатывает Supabase. Проверяйте собственные настройки доступа, домены перенаправления, политику хранения/удаления данных и применимые требования к приватности перед публичным запуском. Ни одна конфигурация не даёт абсолютной гарантии безопасности.

### Что такое SMTP и как подключить отправку писем

SMTP — стандартный способ, которым сервис отправляет электронные письма. Supabase использует его для писем подтверждения адреса и сброса пароля. Встроенная тестовая отправка подходит только для проб: у неё могут быть лимиты и ограничения на адреса получателей, поэтому пользователям сайта письма могут не приходить.

Для публичного сайта подключите почтового провайдера (например, Resend, Brevo или Amazon SES):

1. Создайте аккаунт у выбранного провайдера и добавьте домен, с которого будут уходить письма, например `mail.example.com`.
2. Подтвердите владение доменом. Провайдер покажет DNS-записи для SPF и DKIM, а иногда и DMARC. Добавьте их у регистратора домена/DNS-хостинга точно по инструкции провайдера; дождитесь проверки домена в его панели. Это подтверждает отправителя и помогает письмам не попадать в спам. Для проверки записей используйте инструменты своего провайдера; не публикуйте приватные SMTP-пароли.
3. В панели провайдера создайте SMTP-доступ/SMTP credentials и скопируйте сервер (host), порт, имя пользователя и пароль. Это именно SMTP credentials, не пароль от почты и не API-ключ Supabase. Секреты храните только в менеджере паролей.
4. В Supabase откройте **Project Settings → Authentication → SMTP Settings** (в некоторых версиях панели: **Authentication → Settings → SMTP Settings**). Включите **Enable Custom SMTP** и внесите host, port, username и password от провайдера, а также имя и адрес отправителя на подтверждённом домене, например `Код <no-reply@mail.example.com>`. Сохраните настройки.
5. Проверьте шаблоны писем подтверждения и восстановления пароля в разделе шаблонов Auth. В ссылках используйте redirect URL приложения, не сторонний неизвестный адрес.
6. Зарегистрируйте тестовый аккаунт на свой адрес, нажмите ссылку подтверждения и проверьте, что браузер возвращается на ваш сайт. Отдельно проверьте сброс пароля и папку «Спам». В панели почтового провайдера посмотрите журнал доставки.

Стоимость, лимиты писем и нужные SMTP-поля зависят от провайдера. Никогда не добавляйте SMTP-пароль в `config.js`, исходный код, GitHub или клиентские переменные: вводите его только в защищённые SMTP-настройки проекта Supabase.

## Локальный запуск

Требуется Node.js 18 или новее. Дополнительные npm-пакеты не нужны.

```powershell
node server.js
```

Откройте `http://localhost:3000`. Если порт 3000 занят, задайте другой перед запуском:

```powershell
$env:PORT = "3001"
node server.js
```

Проверить сборочный скрипт локально можно командой `npm run build`; без переменных окружения Vercel он не изменяет SEO-метаданные.
