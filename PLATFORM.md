# Код — образовательная платформа

## Запуск на Windows

Нужен Node.js 22.13+ (проверено на 24.21). Зависимостей npm нет.

    cd D:\Py_site\learning_PYTHON
    npm.cmd start

Откройте http://localhost:3000. В PowerShell используйте npm.cmd, если npm.ps1 запрещён политикой системы.
Главная: index.html. Учебное приложение с 90 уроками Python: learn.html.
Для авторизации нужен Node-сервер: открытие HTML двойным кликом не поддерживается.

## Возможности

- Адаптивная главная, меню, фильтры направлений и поиск по названию, навыкам и школе.
- Независимая подборка пяти указанных платформ. Курсы школ открываются в новой вкладке, встроенный Python работает на этом сайте.
- Подбор направления по трём вопросам, с учётом интересов, опыта и формата старта.
- Настоящее выполнение Python в Web Worker через Pyodide. Первый запуск требует интернет.
- Регистрация, вход, выход, сохранение сессии, личный кабинет и синхронизация прогресса.
- Восстановление пароля одноразовым резервным кодом. При использовании код заменяется, старые сессии отзываются. Письма в локальном режиме не отправляются.

## Аккаунты и хранение

В config.js выбран authProvider: "local". Сервер создаёт data/accounts.sqlite.
Данные сохраняются после перезапуска. Каталог data/ исключён из Git и недоступен через HTTP.

Пароли хешируются scrypt с отдельной случайной солью. В БД хранятся только SHA-256 хеши случайных токенов сессий и резервных кодов.
Сессия: HttpOnly, SameSite=Strict, срок 7 дней. POST-запросы требуют совпадения Origin и JSON Content-Type.
Регистрация, вход и восстановление ограничены 30 попытками за 15 минут на IP.
Ограничитель расположен в памяти одного процесса; для нескольких экземпляров нужен общий limiter.

Email в локальном режиме — идентификатор, не подтверждённый адрес. SMTP не подключён.
Резервный код показывается только после регистрации или восстановления. Его можно скачать из личного кабинета.
Если пароль и код потеряны, автоматическое восстановление невозможно.

Для эксплуатации нужен постоянный Node-сервер с диском и HTTPS. Задайте:

    NODE_ENV=production
    PUBLIC_ORIGIN=https://your-domain.example
    COOKIE_SECURE=true
    DATABASE_PATH=/persistent/path/accounts.sqlite

Это пример переменных окружения, а не готовые адреса. Делайте резервные копии SQLite штатным backup-механизмом; при файловом копировании остановите сервер, учитывайте WAL/SHM.

## Альтернативный Supabase

Существующая интеграция сохранена. Адрес проекта из исходного config.js не разрешался в DNS при проверке; его работоспособность не подтверждена.

1. Укажите authProvider: "supabase", рабочие supabaseUrl и публичный supabaseAnonKey в config.js.
2. Выполните supabase-schema.sql в своём проекте: таблица прогресса защищена RLS.
3. В Auth URL Configuration задайте Site URL и разрешите redirect для главной страницы и /learn.html.
4. Включите подтверждение email, настройте SMTP и проверьте доставку писем.

Supabase-аккаунты и локальные аккаунты независимы; автоматической миграции нет.
Нельзя публиковать SQLite-версию как набор статических файлов: API требует Node-сервер.
Для статической публикации сначала настройте рабочий Supabase. Сборка блокирует Vercel-публикацию локального режима.

## Проверка

    npm.cmd test
    npm.cmd run build

Серверные тесты используют временные базы и проверяют регистрацию, валидацию, согласие, CSRF, пароли, изоляцию прогресса, logout, восстановление, отзыв сессий и ограничение попыток.

Вёрстка содержит правила для ширин 320–1440+ px, клавиатурный фокус, нативные dialog/details, текстовые статусы и reduced motion.
Визуальная проверка в браузере не завершена: инструмент управления Chrome остановился из-за невозможности определить URL. Не считать это пройденным браузерным тестом.
